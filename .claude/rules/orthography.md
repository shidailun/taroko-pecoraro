# Modern-spelling map — structure and invariants

Loads only when working on orthography files. Batch-by-batch evidence for every
claim here is in `.claude/notes/map-history.md`.

## Pipeline

`modernize()` lookup order: **`WORD_OVERRIDES` → `MODERN_MAP` → `charRules()`**.

`site/modern_map.js` is generated by `tools/orthography/build_modern_map.py`.
`WORD_OVERRIDES` (app.js) is invisible to the generator, so a key in
`OVERRIDE_KEYS` is inert in the map — entries written there are silently ignored.

Char rules are `o→u`, `l→r`, `x→h` only, cross-checked against
`Truku_Omnibus.xlsx`. `i→y` and `q↔k` were tested and excluded as too
inconsistent. `ts→c` was tested and rejected — modern Truku writes `ts` too.

Conversion is word-by-word because blanket rules corrupt words that are already
valid modern Truku (`malu`→*maru, `do`→*du, `lukus`→*rukus).

## Map tiers

- **id** — original spelling already attested in the omnibus; left unchanged.
  Also protects loanwords (`lemon`) from the char rules.
- **M** — hand-curated, gloss-verified (`tools/orthography/manual_map.json`).
- **N** — name freezes. Attestation outranks the freeze (see MIXALASI).
- **X** — lexical substitution, shown in brackets.
- Others (P, E, G, R, S, W) — projected/inferred; see `map-history.md`.

**An identity claim is not a no-op — it blocks `charRules()`.** Where the char
rules would have been right, mapping a token to itself is strictly worse than
having no entry: it suppresses a correct fix and turns a green guess into a brown
claim. This is the one tier where a homonym is actively harmful.

**But a shape-only test over the id tier proposes ~8 wrong changes per right
one.** Of 2,048 identity claims: 1,203 inert, 279 right, 526 blind, 17 suspect —
and reading the glosses killed 12 of the 17. Never act on shape alone here.

**An identity entry in tier M is a verdict reached at a particular time** ("no
modern form found") and may be overturned when a family turns up attested.

**His own tag can name the modern spelling.** A bracketed variant that is the
*fuller* form is direct evidence, not a guess. Root tags join the token census as
**new types only** — bumping an existing count re-orders the frequency walk and
flips decisions elsewhere.

## Generator invariants

- **No diacritic ever leaves the generator.** `plain()` (ç→x, marks stripped) runs
  over every tier's output. The app cannot repair this — a map hit short-circuits
  `charRules()`.
- **No vowelless modern word leaves it either.** Any non-X mapping whose value has
  no `aeiou` is dropped and the token returns to green. Must NOT require the
  *input* to have a vowel — he writes schwa as `'`.
- **The generator is deterministic.** Every `for … in set(…)` is wrapped in
  `sorted()`; all length-only sorts carry a total key. Keep it that way — diffing
  `modern_map.js` to audit a change is worthless without it.
- **Two elision marks, `'` and `"`,** are both real (181 types / 400 occurrences
  carry `"`; whole paradigms use it consistently). `wordKey()` folds
  `" ’ ʼ ʔ → '` for lookup and `charRules()` must fold them on OUTPUT too.
  Some marks are deliberate and are the only thing separating two words.

## Corpus rules

- **MAX across readings, SUM within one.** The xlsx is an export *of* the
  parquets; adding both counts every shared utterance twice and breaks the `>= 2`
  gate. Within one parquet, two plain types that `norm()` to one key do sum.
- **The `>= 2` bar is universal**, and load-bearing hardest where a hit
  *subtracts* — one mis-heard token stripped `embrinah`, `empurug`, `emphuqil`.
